## Was ist ein Lambda-Ausdruck?

Ein Lambda-Ausdruck ist im Kern eine **anonyme Funktion** – also eine Funktion ohne Namen, die du direkt als Wert übergeben kannst.

**Deine Vermutung:** "Lambda vergleicht etwas" – das ist nicht ganz richtig, aber du bist auf der richtigen Spur! Ein Lambda **führt etwas aus** – was genau, das bestimmst du selbst. Es *kann* vergleichen, aber auch rechnen, umwandeln, filtern, usw.

---

## Die Syntax in Java

```java
// Allgemeine Form:
parameter -> ausdruck

// Beispiele:
i -> i + 3           // Nimmt eine Zahl, gibt Zahl + 3 zurück
i -> i > 5           // Nimmt eine Zahl, gibt true/false zurück (das ist dein "Vergleich"!)
(a, b) -> a + b      // Nimmt zwei Zahlen, gibt ihre Summe zurück
```

Du kennst das aus Python bereits:
```python
# Python:
lambda i: i + 3
lambda i: i > 5

# Java macht dasselbe, nur ohne das Wort "lambda":
i -> i + 3
i -> i > 5
```

---

## Was sind Funktionale Interfaces?

In Java kann man eine Funktion nicht einfach so übergeben – man braucht einen **Typ** dafür. Dieser Typ heißt **Funktionales Interface**.

Java hat fertige funktionale Interfaces im Package `java.util.function`. Hier die vier, die in eurer Aufgabe relevant sind:

| Interface | Was es tut | Eingabe → Ausgabe |
|---|---|---|
| `UnaryOperator<T>` | Nimmt einen Wert, gibt denselben Typ zurück | `Integer` → `Integer` |
| `IntBinaryOperator` | Nimmt zwei `int`s, gibt einen `int` zurück | `int, int` → `int` |
| `BiFunction<A, B, R>` | Nimmt zwei Werte, gibt einen anderen Typ zurück | `Integer, Integer` → `String` |
| `Predicate<T>` | Nimmt einen Wert, gibt `true` oder `false` zurück | `Integer` → `boolean` |

> 💡 **Das Predicate ist dein "Vergleich"!** `i -> i > 5` ist ein `Predicate<Integer>` – es testet eine Bedingung und gibt `true` oder `false` zurück.

---

## Wie hängt das mit der Aufgabe zusammen?

Schau dir mal diesen Methodenaufruf aus der `main`-Methode an:

```java

```

Hier wird der Methode `applyMathToOneInt` ein Lambda `i -> i + 3` übergeben. Das Lambda:

Die Methode sieht aktuell so aus:

Das `Object o` ist der Platzhalter – deine Aufgabe ist es, `Object` durch das **passende funktionale Interface** zu ersetzen und dann das Lambda in der Methode anzuwenden.

## Was ist die Ausgangssituation?

Du bekommst eine fertige Java-Klasse `FunctionalInterfaces`, die **4 Methoden** enthält. Diese Methoden sind aktuell **kaputt** – sie haben alle denselben Fehler:

Der Parameter für das Lambda ist überall als `Object o` deklariert. Das ist falsch, weil Java nicht weiß, wie es ein `Object` als Funktion ausführen soll.

```java

```

---

## Was sind deine zwei Aufgaben pro Methode?

### Aufgabe 1️⃣: Richtiges Interface einsetzen
Ersetze `Object o` durch das **passende funktionale Interface** – basierend darauf, was das Lambda macht.

### Aufgabe 2️⃣: Interface anwenden
Implementiere die Methode so, dass das Lambda auch **wirklich aufgerufen** wird.

---

## Die 4 Methoden im Überblick

| Methode | Lambda aus `main` | Was passiert? |
|---|---|---|
| `applyMathToOneInt` | `i -> i + 3` | 1 `int` rein, 1 `int` raus |
| `applyMathToTwoInts` | `(int a, int b) -> (a % 3) + (b * 5)` | 2 `int`s rein, 1 `int` raus |
| `concatenateInts` | `(a, b) -> "First: " + a + ", Second: " + b` | 2 `int`s rein, 1 `String` raus |
| `filterIntegers` | `i -> i > 5` | 1 `int` rein, `true`/`false` raus |

---

## Wie rufst du ein funktionales Interface auf?

Jedes Interface hat eine **eigene Methode**, mit der du das Lambda ausführst:

| Interface | Aufruf-Methode |
|---|---|
| `UnaryOperator<Integer>` | `.apply(wert)` |
| `IntBinaryOperator` | `.applyAsInt(wert1, wert2)` |
| `BiFunction<Integer, Integer, String>` | `.apply(wert1, wert2)` |
| `Predicate<Integer>` | `.test(wert)` |

---

## Konkretes Beispiel zum Verständnis

Wenn du `applyMathToOneInt(10, i -> i + 3)` aufrufst, soll die Methode intern das Lambda auf `10` anwenden und `13` zurückgeben. Das sähe dann so aus:

```java
public static int applyMathToOneInt(int i, UnaryOperator<Integer> o) {
    return o.apply(i);  // ruft das Lambda auf: i -> i + 3, also 10 + 3 = 13
}
```

   **Decurrying mit `Function.uncurried`**
   
   Die inverse Operation, **Decurrying**, konvertiert eine curried Funktion zurück in uncurried Form:
   
   ```scala
   val uncurried = Function.uncurried(curried)
   val result = uncurried(1, 2, 3)  // 6
   ```
   
   **Typinferenz:** `Function.uncurried` leitet aus dem curried Typ den entsprechenden uncurried Typ ab:
   - Eingabe: `Int => Int => Int => Int`
   - Ausgabe: `(Int, Int, Int) => Int`
   
   **Praktische Relevanz:** Decurrying ist nötig, wenn eine curried Funktion an eine Schnittstelle übergeben werden muss, die Tupel-Argumente erwartet (z.B. ältere APIs, Java-Interoperabilität).
   
   **Zusammenfassung der Transformationen:**
   | Richtung | Methode | Syntax |
   |----------|---------|--------|
   | Uncurried → Curried | `.curried` | `f.curried` |
   | Curried → Uncurried | `Function.uncurried` | `Function.uncurried(f)` |

   ## Intermediate Operations im Detail
   
   **Definition**: Operationen, die einen Stream entgegennehmen und einen **neuen Stream** zurückgeben.
   
   **Eigenschaften:**
   
   | Eigenschaft | Bedeutung |
   |-------------|-----------|
   | **Lazy** | Werden nicht sofort ausgeführt |
   | **Verkettbar** | Rückgabe ermöglicht Method Chaining (`a.b().c().d()`) |
   | **Auslösung** | Erst bei Terminal Operation |
   
   **Typisches Muster:**
   ```java
   stream.op1().op2().op3().terminal()  // op1, op2, op3 = lazy
   ```
   
   **Warum Lazy?**
   - Effizienz: Nicht alle Elemente müssen verarbeitet werden (Short-Circuiting)
   - Optimierung: Das Framework kann Operationen fusionieren
   - Unendliche Streams: Erst Terminal Operation begrenzt die Verarbeitung
   
   **Beispiele**: `filter`, `map`, `sorted`, `distinct`, `limit`, `skip`, `peek`

   val left = names.foldLeft("BEGIN")((acc, name) => s"($acc + $name)")
   // Ergebnis: "(((BEGIN + n1) + n2) + n3)"
   
   // foldRight: Akkumulator rechts  
   val right = names.foldRight("BEGIN")((name, acc) => s"($name + $acc)")
   // Ergebnis: "(n1 + (n2 + (n3 + BEGIN)))"
   ```

   val prices = catalog.take(4).map(_.price)

   ```

# `IntBinaryOperator` – Detaillierte Erklärung! 🔍

## Was ist `IntBinaryOperator`?

`IntBinaryOperator` ist ein funktionales Interface aus dem Java-Package `java.util.function`. Der Name verrät schon alles:

- **`Int`** → arbeitet mit `int`-Werten (primitiver Typ, kein `Integer`-Objekt)
- **`Binary`** → braucht **zwei** Eingaben
- **`Operator`** → gibt denselben Typ zurück wie die Eingabe

---

## Die Signatur

```java
// Was IntBinaryOperator intern definiert:
int applyAsInt(int left, int right);
```

Also: **Zwei `int`s rein → Ein `int` raus**

---

## Konkrete Beispiele

```java
// Addition:
IntBinaryOperator addition = (a, b) -> a + b;
addition.applyAsInt(10, 5);  // → 15

// Multiplikation:
IntBinaryOperator mult = (a, b) -> a * b;
mult.applyAsInt(10, 5);      // → 50

// Aus eurer Aufgabe:
IntBinaryOperator aufgabe = (int a, int b) -> (a % 3) + (b * 5);
aufgabe.applyAsInt(10, 23);  // → (10 % 3) + (23 * 5) = 1 + 115 = 116
```

---

## Warum `IntBinaryOperator` und nicht `BiFunction<Integer, Integer, Integer>`?

Das ist eine wichtige Frage! Beide würden funktionieren, aber:

| | `IntBinaryOperator` | `BiFunction<Integer, Integer, Integer>` |
|---|---|---|
| **Typ** | primitives `int` | `Integer`-Objekt |
| **Performance** | ✅ Schneller (kein Boxing) | ❌ Langsamer (Auto-Boxing nötig) |
| **Lesbarkeit** | ✅ Klarer für reine `int`-Operationen | Umständlicher |

> 💡 **Boxing** bedeutet: Java verpackt einen primitiven `int` in ein `Integer`-Objekt. Das kostet extra Speicher und Zeit. `IntBinaryOperator` vermeidet das komplett.

public static String concatenateInts(int a, int b, BiFunction<Integer, Integer, String> o) {
    return o.apply(a, b);
}

public static List<Integer> filterIntegers(List<Integer> nums, Predicate<Integer> o) {
    List<Integer> output = new ArrayList<>();
    for (int i : nums) {
        if (o.test(i)) {
            output.add(i);
        }
    }
    return output;
}

   Diese Folie demonstriert **konkret**, wie Lazy Evaluation die Anzahl der Operationen drastisch reduziert.

   |---------|:---------------------:|:------------------:|:---:| :-------: |

   | Kochbuch | ✓ | ✗ | – | – |
   | Smartphone | ✓ | ✗ | – | – |
   | **Bio-Honig** | ✓ | ✓ | ✓ | **✓ STOP** |
   | ... | – | – | – | – |
   
   ### Operationenzählung:
   - **Eager-Ausführung** (hypothetisch): 25 + 25 + 25 + 1 = **76 Operationen**
   - **Lazy-Ausführung** (tatsächlich): 25 + 21 + 3 + 1 = **50 Operationen**

val paare = for {

} yield (a, b)
// Ergebnis: List((1,10), (1,20), (2,10), (2,20))

# Die `for`-Notation in Scala – Detaillierte Erklärung! 🎯

## Das Grundprinzip

Du kennst aus Python die **List Comprehension**:

```python
# Python:
result = [x * 2 for x in liste]
```

In Scala heißt das Äquivalent **for-Notation** und sieht so aus:

```scala
// Scala:
val result = for {
    x <- liste
} yield x * 2
```

> 💡 **`<-`** bedeutet: "für jedes Element x aus liste"
> 💡 **`yield`** bedeutet: "gib diesen Wert zurück und sammle ihn in einer neuen Liste"

---

## Die 3 wichtigsten Bausteine

### Baustein 1️⃣: Iteration (`<-`)
```scala
for {
    x <- liste    // "für jedes x in liste"
} yield x
```

### Baustein 2️⃣: Filter (`if`)
```scala
for {
    x <- liste if x > 5    // "aber nur wenn x größer als 5 ist"
} yield x
```

### Baustein 3️⃣: Zwischenwerte (`=`)
```scala
for {
    x <- liste
    y = x * 2    // y ist ein Zwischenwert, kein neues Element!
} yield y
```

---

## Kombinierte Beispiele

### Beispiel 1: Einfache Transformation
```scala
val zahlen = List(1, 2, 3, 4, 5)

val verdoppelt = for {
    z <- zahlen
} yield z * 2
// Ergebnis: List(2, 4, 6, 8, 10)
```

### Beispiel 2: Mit Filter
```scala
val zahlen = List(1, 2, 3, 4, 5)

val groesserAlsDrei = for {
    z <- zahlen if z > 3
} yield z
// Ergebnis: List(4, 5)
```

### Beispiel 3: Zwei Listen kombinieren
```scala
val liste1 = List(1, 2)
val liste2 = List(10, 20)

val paare = for {
    a <- liste1
    b <- liste2
} yield (a, b)
// Ergebnis: List((1,10), (1,20), (2,10), (2,20))
```

### Beispiel 4: Mit Zwischenwert und Filter
```scala
val zahlen = List(1, 2, 3, 4, 5)

val ergebnis = for {
    z <- zahlen
    verdoppelt = z * 2      // Zwischenwert berechnen
    if verdoppelt > 4       // auf Zwischenwert filtern
} yield verdoppelt
// Ergebnis: List(6, 8, 10)
```

## Tupel direkt entpacken

Das ist besonders wichtig für unsere Aufgabe! Wenn du eine Liste von Tupeln hast, kannst du die Werte direkt in der `for`-Notation entpacken:

```scala
val studenten = List(("Willi", 373583, 2), ("Anselma", 476749, 1))

val namen = for {
    (name, matnr, versuch) <- studenten    // direkt entpacken!
} yield name
// Ergebnis: List("Willi", "Anselma")

// Mit Filter:
val zweitversuch = for {
    (name, matnr, versuch) <- studenten if versuch == 2
} yield name
// Ergebnis: List("Willi")
```

## Wichtig: `.toList` am Ende

Die `for`-Notation über einen **Iterator** (wie `lines` aus der Datei) gibt keinen `List` zurück, sondern einen `Iterator`. Du musst am Ende `.toList` aufrufen:

```scala
val lines = Source.fromResource(fileName).getLines()  // Iterator!

val result = for {
    line <- lines
} yield line

result.toList  // Iterator → List
```
