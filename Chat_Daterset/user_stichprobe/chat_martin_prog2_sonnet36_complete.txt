   ## Eagerness vs. Laziness – Vergleich
   
   Diese Folie demonstriert **konkret**, wie Lazy Evaluation die Anzahl der Operationen drastisch reduziert.
   
   ### Szenario: Finde erstes verfügbares Produkt unter 10€
   
   | Produkt | Filter 1 (verfügbar?) | Filter 2 (< 1000?) | Map | FindFirst |
   |---------|:---------------------:|:------------------:|:---:| :-------: |
   | Laptop | ✓ | ✗ | – | – |
   | T-Shirt | ✓ | ✗ | – | – |
   | Kochbuch | ✓ | ✗ | – | – |
   | Smartphone | ✓ | ✗ | – | – |
   | **Bio-Honig** | ✓ | ✓ | ✓ | **✓ STOP** |
   | ... | – | – | – | – |
   
   ### Operationenzählung:
   - **Eager-Ausführung** (hypothetisch): 25 + 25 + 25 + 1 = **76 Operationen**
   - **Lazy-Ausführung** (tatsächlich): 25 + 21 + 3 + 1 = **50 Operationen**
   
   **Kritische Erkenntnis**: Nach `Bio-Honig` (erstes Treffer) bricht `findFirst()` die Verarbeitung ab. Die restlichen 20 Produkte werden **nie** betrachtet – das ist **Short-circuiting** in Aktion.
   
   Die Tabelle zeigt auch, dass `Designer-Schal` und `Winterjacke` bereits in Filter 1 scheitern (nicht verfügbar), also Filter 2 nie erreichen.

   ## Die drei Bestandteile einer Stream-Pipeline
   
   Jede Stream-Pipeline folgt einem festen Schema:
   
   ```
   ┌─────────────────┐    ┌─────────────────────────┐    ┌─────────────────┐
   │   DATENQUELLE   │ →  │  INTERMEDIATE OPERATIONS │ →  │ TERMINAL OP.    │
   │  (Source/Sink)  │    │  (0...n Transformationen)│    │ (Ergebnis/Seit- │
   │                 │    │                          │    │  effekte)       │
   │ catalog.stream()│    │ filter, sorted, map...   │    │ collect, forEach│
   └─────────────────┘    └─────────────────────────┘    └─────────────────┘
   ```
   
   **Regeln:**
   1. **Genau eine Datenquelle** – startet den Stream
   2. **Beliebig viele Intermediate Operations** (auch 0) – verändern den Stream
   3. **Genau eine Terminal Operation** – beendet die Pipeline und produziert das Ergebnis
   
   **Merksatz**: *"Quelle öffnet, Zwischenschritte formen, Terminal schließt"*

# Funktionale Interfaces in Java

Hier ist eine vollständige Übersicht aller relevanten funktionalen Interfaces, die du für diese Aufgabe brauchst:

---

## Was ist ein Funktionales Interface überhaupt?

Ein funktionales Interface ist ein Interface mit **genau einer abstrakten Methode**. Das macht es kompatibel mit **Lambda-Ausdrücken** – der Lambda-Ausdruck implementiert automatisch diese eine Methode.

---

## Die wichtigsten Funktionalen Interfaces

| Interface | Methode | Nimmt | Gibt zurück | Beispiel-Lambda |
|---|---|---|---|---|
| `UnaryOperator<T>` | `.apply(T t)` | 1 Wert vom Typ T | Wert vom Typ T | `i -> i + 3` |
| `BinaryOperator<T>` | `.apply(T t1, T t2)` | 2 Werte vom Typ T | Wert vom Typ T | `(a, b) -> a + b` |
| `IntBinaryOperator` | `.applyAsInt(int a, int b)` | 2 `int`-Werte | `int` | `(a, b) -> a % 3 + b * 5` |
| `BiFunction<T, U, R>` | `.apply(T t, U u)` | 2 Werte (Typ T, U) | Wert vom Typ R | `(a, b) -> "Zahl: " + a` |
| `Predicate<T>` | `.test(T t)` | 1 Wert vom Typ T | `boolean` | `i -> i > 5` |
| `Function<T, R>` | `.apply(T t)` | 1 Wert vom Typ T | Wert vom Typ R | `s -> s.length()` |
| `Consumer<T>` | `.accept(T t)` | 1 Wert vom Typ T | nichts (`void`) | `i -> System.out.println(i)` |
| `Supplier<T>` | `.get()` | nichts | Wert vom Typ T | `() -> 42` |

---

## 💡 Die entscheidende Frage bei der Auswahl:

```
Was nimmt das Lambda rein?  →  Was gibt es zurück?  →  Welches Interface passt?
```

**Beispiel:**
```
i -> i + 3
```
- Nimmt **einen** `int` rein
- Gibt **einen** `int` zurück (gleicher Typ!)
- → `UnaryOperator<Integer>` ✅

---

   - **Höchste Parallelisierbarkeit**: Elemente können unabhängig verarbeitet werden

   - **Keine Zwischenspeicherung**: Speichereffizient

   - `map(Product::getName)` – Transformiert nur aktuelles Element
   - `flatMap()` – Entpackt verschachtelte Strukturen elementweise

   ## Streams als Sequenz von Elementen
   
   Die visuelle Darstellung `catalog -> filter -> sorted -> map -> collect -> productNames` verdeutlicht den **Datenfluss** in einer Pipeline.
   
   **Fundamentale Eigenschaften von Streams:**
   
   | Eigenschaft | Bedeutung |
   |-------------|-----------|

   - Potenzielle Parallelisierung ohne Code-Änderung
   - Unendliche Streams (z.B. `Stream.iterate(0, n -> n + 1)`)
