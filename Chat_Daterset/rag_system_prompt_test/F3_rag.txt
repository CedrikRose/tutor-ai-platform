  # Java Type Casting and Operators
  
  ## Type Casting in Java
  
  In the cardboard box analogy, it is also possible to squeeze a fridge into a shoe-sized box: We just need to cut off all parts that do not fit. For Java types, this is the exact same thing: When we squeeze a larger type into a smaller type (e.g., to store it inside a variable of that type), we potentially lose information. Just think about transforming a `long` into an `int`. What happens under the hood is that we simply drop the first 32 bits – any information on numbers outside the interval \([-2^{31}; 2^{31} - 1]\) will simply be lost.
  
  To still tell the compiler to go ahead (essentially saying “yes, I’m aware that I’m potentially losing information here”), we need to add an explicit typecast. For explicit typecasts, the syntax is:
  
  ```java
  (int) variableName
  ```
  
  ### Example
  
  ```java
  long largeNumber = 1234567890123L;
  int smallerNumber = (int) largeNumber; // Explicit typecast
  System.out.println(smallerNumber); // Output may lose information
  ```

  ## Integer vs. Floating Point Division
  
  Java differentiates between integer division and floating point division.
  
  - Integer division:
  ```java
  int result = 5 / 2; // result will be 2
  ```
  
  - Floating point division:
  ```java
  double result = 5.0 / 2.0; // result will be 2.5
  ```
  
  ### Why does `5 / 2.0` print `2.5`?
  
  When combining an integer and a floating point number, the Java Virtual Machine (JVM) checks the types of the operands. If one operand can be implicitly typecast to a floating point type, the entire expression will be evaluated as a floating point operation.

  ### Concatenation with the `+` Operator
  
  The `+` operator can also be used to concatenate strings. For example:
  
  ```java
  String greeting = "Hello, " + "World!"; // greeting will be "Hello, World!"
  ```
  
  If either operand of the `+` operator is a string, the result will always be a concatenation of both operands, regardless of the type of the other operand.
  
  ### Expression Evaluation Order
  
  When using expressions, it's important to consider the order of operations:
  
  1. Multiplication (`*`) and Division (`/`) are evaluated before Addition (`+`) and Subtraction (`-`).
  2. Parentheses are evaluated first for clarity.
  3. Assignment operators are evaluated last.
  4. If the precedence is still unclear, expressions are evaluated from left to right.
  
  For example:
  
  ```java
  int result1 = 10 + 2 * 3; // result1 will be 16
  int result2 = (10 + 2) * 3; // result2 will be 36
  ```
  
  ### Explicit Typecasting
  
  Explicit typecast operators are evaluated on the operand to the right of them right after brackets. For example:
  
  ```java
  double result = (double) 5 / 2; // result will be 2.5
  ```
  
  This ensures that the division is performed as a floating point operation.

ASSISTENT: # Typecasts in Java

## Grundkonzept

Ein **Typecast** bezeichnet die Umwandlung eines Datentyps in einen anderen. Das Kursmaterial verwendet dafür eine anschauliche Analogie:

> Stell dir vor, du möchtest etwas von einer Schachtel in eine andere Schachtel umladen – je nach Größenverhältnis funktioniert das unterschiedlich gut.

---

## 1. Implizite Typecasts (automatisch)

Wenn man etwas **Kleines in etwas Größeres** packt, passiert das automatisch – ohne dass man eingreifen muss:

```
byte → short → int → long → float → double
```

Außerdem gilt:
```
char → int (und größer)
```

**Beispiel:**
```java
int kleineZahl = 42;
double großeZahl = kleineZahl; // funktioniert automatisch
```

---

## 2. Explizite Typecasts (manuell)

Wenn man etwas **Großes in etwas Kleineres** packt, gehen potenziell **Informationen verloren** (wie ein Kühlschrank in eine Schuhschachtel quetschen). Deshalb muss man dem Compiler explizit sagen, dass man sich dessen bewusst ist.

**Syntax:**
```java
(zielTyp) variablenName
```

**Beispiel:**
```java
long großeZahl = 1234567890123L;
int kleineZahl = (int) großeZahl; // Expliziter Typecast
```
⚠️ Dabei werden einfach die **ersten 32 Bits abgeschnitten** – Zahlen außerhalb von $[-2^{31};\, 2^{31}-1]$ gehen verloren.

---

## 3. Praktisches Beispiel: Division

```java
int result1 = 5 / 2;          // = 2  (Ganzzahldivision)
double result2 = (double) 5 / 2; // = 2.5 (Fließkommadivision)
```

Sobald **ein Operand** als `double` vorliegt, wertet die JVM den gesamten Ausdruck als Fließkommaoperation aus.

---
