  ### Overview of Object-Oriented Programming
  
  Object-Oriented Programming (OOP) is a programming paradigm that uses "objects" to represent data and methods to manipulate that data. The key concepts of OOP include:
  
  - **Classes and Objects**
  - **Encapsulation**
  - **Inheritance**
  - **Polymorphism**
  
  ### 1. Classes and Objects
  
  A class is a blueprint for creating objects. An object is an instance of a class.
  
  ```python
  class Dog:
  def __init__(self, name):
  self.name = name
  
  def bark(self):
  return f"{self.name} says woof!"
  
  # Creating an object of the Dog class
  my_dog = Dog("Buddy")
  print(my_dog.bark())  # Output: Buddy says woof!
  ```
  
  ### 2. Encapsulation
  
  Encapsulation is the bundling of data and methods that operate on that data within one unit, typically a class. It restricts direct access to some of the object's components.
  
  ```python
  class BankAccount:
  def __init__(self, balance=0):
  self.__balance = balance  # Private attribute
  
  def deposit(self, amount):
  self.__balance += amount
  
  def get_balance(self):
  return self.__balance
  
  account = BankAccount()
  account.deposit(100)
  print(account.get_balance())  # Output: 100
  ```
  
  ### 3. Inheritance
  
  Inheritance allows a class to inherit attributes and methods from another class.
  
  ```python
  class Animal:
  def speak(self):
  return "Animal speaks"
  
  class Cat(Animal):
  def speak(self):
  return "Cat meows"
  
  my_cat = Cat()
  print(my_cat.speak())  # Output: Cat meows
  ```
  
  ### 4. Polymorphism
  
  Polymorphism allows methods to do different things based on the object it is acting upon.
  
  ```python
  def animal_sound(animal):
  print(animal.speak())
  
  animal_sound(my_cat)  # Output: Cat meows
  animal_sound(Dog("Rex"))  # Output: Rex says woof!
  ```
  
  ### Summary
  
  Object-Oriented Programming is a powerful paradigm that helps in organizing code and making it more reusable and maintainable.

  ### Block Scope
  
  We already talked briefly about blocks, but this will become more important later: Blocks can contain other blocks, and variable names need to be unique per block. This includes its parent and child blocks but not sibling blocks.
  
  For example, if block A contains blocks B and C (both at the same level), then variable names used in A cannot be used in B and C. Variable names used in B cannot be used in A but can be used in C. This is the exact opposite of common usage of names in humans: You might have the same first name as your parents or grandparents, but you are very unlikely to have the same first name as your siblings.
  
  Likewise, variables are visible (i.e., accessible) within the same block and all its contained child blocks. For example, block A again contains blocks B and C, but block C also contains block D. Then, variables declared in A are visible in A, B, C, and D; variables declared in B are only visible in B; variables declared in C are visible in C and D; and variables declared in D are visible only in D.

## 🏗️ Instanzvariablen & -methoden

**Instanzvariablen** gehören zu einem **konkreten Objekt** (einer Instanz einer Klasse).

```java
public class Auto {
    // Instanzvariablen – jedes Auto hat eigene Werte
    String farbe;
    int kilometerstand;
    
    // Instanzmethode – arbeitet mit den Daten DIESES Autos
    public void fahren(int km) {
        kilometerstand += km;  // compound operator aus Vorlesung 2
    }
}
```

```java
Auto auto1 = new Auto();
auto1.farbe = "rot";
auto1.fahren(100);

Auto auto2 = new Auto();
auto2.farbe = "blau";  // unabhängig von auto1!
```

> Jedes `Auto`-Objekt hat seinen **eigenen** `kilometerstand` und seine eigene `farbe`.

---

## 🌐 Klassenvariablen & -methoden (`static`)

**Klassenvariablen/-methoden** gehören zur **Klasse selbst**, nicht zu einer einzelnen Instanz. Sie werden mit dem Schlüsselwort `static` deklariert.

```java
public class Auto {
    // Klassenvariable – wird von ALLEN Autos geteilt
    static int anzahlAutos = 0;
    
    String farbe;  // Instanzvariable
    
    public Auto(String farbe) {
        this.farbe = farbe;
        anzahlAutos++;  // zählt alle erzeugten Autos
    }
    
    // Klassenmethode – kein Zugriff auf Instanzvariablen!
    public static int getAnzahlAutos() {
        return anzahlAutos;
    }
}
```

```java
Auto a1 = new Auto("rot");
Auto a2 = new Auto("blau");

System.out.println(Auto.getAnzahlAutos()); // → 2
// Aufruf über den Klassennamen, nicht über ein Objekt!
```

---

## 📊 Vergleichstabelle

| Merkmal | Instanz | Klasse (`static`) |
|---|---|---|
| **Gehört zu** | Einzelnem Objekt | Der Klasse selbst |
| **Speicher** | Pro Objekt separat | Einmal für alle |
| **Aufruf** | `objekt.methode()` | `Klasse.methode()` |
| **Zugriff auf Instanzvariablen** | ✅ Ja | ❌ Nein |
| **Bekanntes Beispiel** | `auto1.fahren()` | `Math.sqrt()`, `IOTools.read()` |

---

## 🔗 Verbindung zu deinen Kursmaterialien

Das Beispiel `IOTools.read()` aus **Vorlesung 2** ist genau ein Aufruf einer **Klassenmethode** – du rufst sie direkt über den Klassennamen auf, ohne vorher ein `IOTools`-Objekt zu erstellen. Gleiches gilt für `Math.PI` (Klassenvariable) und `Math.sqrt()` (Klassenmethode).

> **Faustregel:** Wenn eine Methode/Variable für **alle Objekte gleich** gilt oder **kein Objekt braucht**, ist `static` sinnvoll.
