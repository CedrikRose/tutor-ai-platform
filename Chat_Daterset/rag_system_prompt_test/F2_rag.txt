  ### Block Scope
  
  We already talked briefly about blocks, but this will become more important later: Blocks can contain other blocks, and variable names need to be unique per block. This includes its parent and child blocks but not sibling blocks.
  
  For example, if block A contains blocks B and C (both at the same level), then variable names used in A cannot be used in B and C. Variable names used in B cannot be used in A but can be used in C. This is the exact opposite of common usage of names in humans: You might have the same first name as your parents or grandparents, but you are very unlikely to have the same first name as your siblings.

Then, variables declared in A are visible in A, B, C, and D; variables declared in B are only visible in B; variables declared in C are visible in C and D; and variables declared in D are visible only in D.

  # Reading from the Console in Java
  
  To read values from the console in Java, there are multiple methods available, but they all require an understanding of object-oriented programming. Unlike some other programming languages, Java does not have a simple and native mechanism for console input.
  
  ## Prog1Tools Library
  
  To simplify console input, we have encapsulated the standard Java mechanisms in the **Prog1Tools** library. Within this library, the **IOTools** class provides straightforward methods for reading various types of values. The naming convention for these methods follows a specific pattern, for example:
  
  - `readInt()`
  - `readDouble()`
  - `readString()`
  
  For reading strings, there are actually two methods: `readLine()` and `readWord()`.
  
  - **`readLine()`** reads an entire line (i.e., until the user hits Enter/Return).
  - **`readWord()`** reads a single word (i.e., any whitespace character will terminate the input).
  
  ### Example Usage
  
  If we want to read an integer, we would call:
  
  ```java
  int userInput = IOTools.readInt();
  ```
  
  This expression evaluates to the integer value that the user typed, which can then be used for further processing, such as assigning it to a variable or printing it to the console.
  
  ## Additional Features of IOTools
  
  The **IOTools** methods come with two additional features:
  
  1. **Input Validation**: When reading an integer, users will be prompted to type an integer number. If they type anything else (e.g., a boolean), the method will reprompt the user.
  
  2. **Custom Prompt**: Each method has a variant that accepts a string parameter. This parameter can be a complex expression, a literal, another method call, or simply the name of a variable.

  Java differentiates between integer division and floating point division.
  
  - Integer division:
  ```java
  int result = 5 / 2; // result will be 2
  ```
  
  - Floating point division:
  ```java
  double result = 5.0 / 2.0; // result will be 2.5

  ### Why does `5 / 2.0` print `2.5`?
  
  When combining an integer and a floating point number, the Java Virtual Machine (JVM) checks the types of the operands. If one operand can be implicitly typecast to a floating point type, the entire expression will be evaluated as a floating point operation.

ASSISTENT: # Variablen in Java

## Grundlegende Definition

Eine Variable ist eine **Abstraktion für eine Speicheradresse** im RAM. Sie hat:
- einen **Namen** (Alias für die Speicheradresse)
- einen **Typ** (bestimmt die Größe des reservierten Speichers)

> 💡 **Analogie:** Man kann sich eine Variable wie einen **Karton** vorstellen – man kann etwas hineinlegen (schreiben) oder hineinschauen (lesen). Kartons gibt es in verschiedenen Größen, genau wie Variablen verschiedene Typen haben.

---

## Deklaration und Zuweisung

```java
// Syntax: typ variablenName = wert;
int number = 10;
String text = "Hello";
```

- **Deklaration** = Speicherplatz reservieren (`int number`)
- **Zuweisung** = Wert speichern (`= 10`)

---

## Primitive Datentypen

| Typ | Größe | Wertebereich |
|-----|-------|-------------|
| `byte` | 8 Bit | −128 bis 127 |
| `short` | 16 Bit | −32.768 bis 32.767 |
| `int` | 32 Bit | −2³¹ bis 2³¹−1 |
| `long` | 64 Bit | −2⁶³ bis 2⁶³−1 |
| `float` | 32 Bit | Dezimalzahlen |
| `double` | 64 Bit | Dezimalzahlen |
| `boolean` | 1 Bit | `true`/`false` |
| `char` | 16 Bit | Unicode-Zeichen |

Zusätzlich gibt es noch **`String`**, der sich teilweise wie ein primitiver Typ verhält.

---

## Wichtige Regeln

### Namenskonventionen
- Namen beginnen mit einem **Kleinbuchstaben**
- **camelCase** verwenden (z.B. `totalAmount`)
- Selbsterklärende Namen wählen (z.B. `numberOfExams` statt `a`)
- Keine Java-Keywords wie `class`, `true`, `null` verwenden

### Standardwerte (für nicht-lokale Variablen)
```
int/long  → 0
float/double → 0.0
boolean   → false
Referenztypen → null
```
⚠️ Es gilt als schlechte Praxis, eine Variable zu verwenden, **ohne ihr vorher einen Wert zuzuweisen**.

### Gültigkeitsbereich (Scope)
- Variablen sind im **eigenen Block** und allen **Kindblöcken** sichtbar
- Variablennamen müssen innerhalb eines Blocks **eindeutig** sein

## Technischer Hintergrund

Im Gegensatz zu Low-Level-Sprachen (z.B. C) muss man in Java den Speicher **nicht manuell freigeben** – das übernimmt der **Garbage Collector** der JVM automatisch.
